## Problem

`patchDemoWorld` + `demoForcedActions` inject fixture ids. Live execute (`parseLoanId` / `parseJobId`) **skips** non-numeric ids (#38/#40). A live 12-tick therefore never repay / default / complete_job on the real book.

## Design

Pass `executeEnabled` into `onTick` context (engine already has `config.executeEnabled`).

**Dry-run (`executeEnabled === false`):** behaviour identical to today. Fixture overlay + `L-1`/`L-2`/`J-demo`/`L-flag`. All existing storyline tests must stay green.

**Live (`executeEnabled === true`):**

1. **Do not overlay fixture loans/jobs.** Keep boom **balance** overlay (gus/hal 5 USDC, bo/cy poor) so buys still fire. Do **not** hide bo pending at t4. Do **not** inject `J-demo`, `L-1`, `L-2`, `L-flag`.
2. **Forced actions use numeric ids from `world` (pre-overlay live snapshot):**
   - `t7 mark_default`: first **Active** numeric loan whose borrower is **not** `bo` (bo already has on-chain default #2 — a second default would `revokeName`, which is gated). Prefer `cy`. If none, **omit** (execute will skip anyway). Do not emit `L-2`.
   - `t9 repay`: `bo`’s **Active** numeric loan. If none, omit. Do not emit `L-1`.
   - Job settle: do not force `J-demo`. Rules/post_job on live world already create numeric jobs; `execute` already threads `jobIdFromTxHash`.
   - `t4 request_loan`: keep the existing “if bo has no pending” force, but it will no-op if `activeLoanOf != 0` (execute skip). Fine.
   - `t9 set_rate`: unchanged (no fixture id).
3. `parseLoanId` / skip of fixtures stays — defence in depth. Do not remove it.
